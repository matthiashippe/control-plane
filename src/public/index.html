Conway-compatible control plane

Conway's onboarding has been broken since July 2026: POST /v1/auth/verify answers 500 or 401 for every fresh wallet, and it still did on September 20, 2026, while the service reported itself healthy with 2 of 8 workers up. Nobody announced a shutdown, and no maintainer has answered an issue since March. This service speaks the same API, so an unmodified automaton runtime can run against it. You change one line of config.

Setup

In ~/.automaton/automaton.json, set the control plane URL:

"conwayApiUrl": "https://cp.hippe.eu"

Then provision and run as usual:

automaton --provision   # SIWE with your wallet, issues an API key
automaton --run         # registers, buys credits from your USDC, starts working

Nothing else changes. Your wallet stays on your machine; this service only ever sees signatures. On the first run the runtime buys the smallest credit tier automatically if the wallet holds enough USDC on Base.

It paid. Is it working?

A top-up is not the same thing as a working agent, and the runtime is quiet about the difference. Two commands tell you where you stand: 

curl -H "Authorization: $YOUR_KEY" https://cp.hippe.eu/v1/credits/history
# {"balance_cents":501,"entries":[...]}
# every booking of yours, newest first: top-ups with their transaction hash,
# inference calls with model, tokens, purchase price and our margin

If the balance is there but the transfer list stays empty, the money arrived and nothing is being spent. In the cases we have seen that is the runtime, not the billing: it only thinks when it can read a balance, so an API key from a different control plane, or a key that never made it into ~/.automaton/config.json, leaves it running and silent with the credit untouched. automaton --provision against this instance issues a key that works here. A key issued anywhere else does not.

Price

Credits are prepaid and priced at the inference cost the service actually pays, times 1.3. The runtime asks for gpt-5.2 and gpt-5-mini from its own routing matrix, whatever inferenceModel says; those names are served as aliases, so you do not have to touch the runtime. The ledger records the purchase cost and the margin for every call, so the markup is one number you can check against the model list below, not a mystery.

What that is in practice: the five-turn run of the same runtime on 19 September 2026 bought 5.5 US cents of inference and was billed 7.2 cents, so roughly one and a half cents per turn; a second run of the same script came to 6.1 cents (goals/2026-09-19-goal-5a-openrouter.md). A turn gets more expensive as the conversation grows, and it depends on which model the runtime's routing matrix picks, so read that as an order of magnitude and not as a rate. At that size 5 USD would have covered a few hundred turns. Every call is one ledger row with its purchase cost and its margin, and GET /v1/credits/balance says what is left.

Top-ups go through x402 (USDC on Base, EIP-3009), settled by an external facilitator. Tiers in USD: 5, 25, 100, 500, 1000, 2500. The runtime signs the payment; the credit is booked in the same transaction as the ledger entry, and a repeated signature never credits twice.

A top-up credits one cent more than you paid: 5 USD becomes 501 cents. The runtime picks its model and token budget from your balance, and the threshold for its best tier is above 500 cents, not at 500. Its bootstrap top-up always takes the smallest tier on offer, so without that cent every new automaton would start one cent below the line it just paid for. Saying it plainly because it also works in our favour: an automaton in the better tier spends more.

You may not need this

Before you pay anyone: the runtime does not think at all when it cannot reach a balance endpoint, but there are two free ways around that, and neither of them is documented upstream. Point the runtime at a local Ollama model, or set the cached balance in its own SQLite state and use your own OpenAI key. Both are written up, with the exact code paths and the one field everybody gets wrong, in docs/without-control-plane.md. If you have hardware that runs a decent local model, that route is better than paying me.
